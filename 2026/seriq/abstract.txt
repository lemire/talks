SERIQ 2026


Titre : Le logiciel libre comme méthode de recherche : de l'article scientifique à des milliards d'appareils


Résumé :

Une bibliothèque libre comme simdjson ou simdutf s'exécute aujourd'hui dans Node.js, dans les
navigateurs web et dans les bases de données : elle traite des données pour des milliards de
personnes, chaque jour. Comment la recherche universitaire se rend-elle jusque-là ?

Le modèle linéaire de l'innovation propose une réponse simple : le professeur réfléchit et
publie, l'ingénieur lit et conçoit, le client consomme. L'histoire réelle des innovations lui
donne rarement raison. Comme le disait Michael Stonebraker, prix Turing : « I never come up with
anything by going off to a mountaintop to think. Instead, my ideas come from two sources: talking
to real users with real problems and then trying to solve them. »

Ma thèse est que le logiciel libre n'est pas seulement un moyen de diffuser des résultats : c'est
une méthode de recherche à part entière. Il impose la reproductibilité, parce que le code et les
bancs d'essai sont publics et que n'importe qui peut vérifier — ou réfuter — nos affirmations. Il
soumet le travail à une évaluation par les pairs bien réelle : les revues de code, les rapports de
bogues et les demandes d'intégration constituent souvent un arbitrage plus exigeant que bien des
comités de lecture. Et il fait venir à nous les données du monde réel : cas adversariaux, entrées
pathologiques, architectures exotiques, charges de travail que personne n'aurait pensé à
fabriquer.

J'illustrerai cette thèse par une histoire concrète, celle de simdjson. Le cycle n'y suit pas
l'ordre attendu : d'abord le code, puis un billet de blogue, GitHub et quelques messages sur X,
puis l'adoption industrielle — et l'article scientifique (avec Geoff Langdale) vient après. Ce
cycle se répète : l'usage révèle le goulot suivant. L'analyse des nombres à virgule flottante
devient le facteur limitant, ce qui mène à l'algorithme Eisel-Lemire, adopté par les bibliothèques
standards de Rust, Go, .NET et C++. La validation UTF-8 pose le même genre de problème et donne
naissance à simdutf, adopté à son tour par Node.js, Bun et les navigateurs. Aucun de ces problèmes
n'était au programme de recherche du départ.

Je terminerai par les tensions honnêtes de cette approche : la maintenance est ingrate et sans
fin — une faille dans votre code est une faille dans Node.js — et les incitatifs académiques sont
mal alignés : les comités comptent les articles, pas les demandes d'intégration.


Plan (10 minutes) :

1. Accroche (1-2 min) — Une bibliothèque libre comme simdjson, simdutf ou fast_float tourne
   aujourd'hui dans Node.js, les navigateurs, les bases de données. Question : comment la
   recherche universitaire finit-elle dans la poche de milliards de gens ?
   - D'où viennent les idées ? La citation de Michael Stonebraker.
   - Le modèle linéaire de l'innovation, et pourquoi il est faux (sous-vêtements et révolution
     industrielle, origine du clavier, ChatGPT : GPU de jeu + textes du web + chat, la relativité
     et le train).

2. Le libre comme méthode de recherche (3-4 min)
   - Reproductibilité : le code et les bancs d'essai sont publics; n'importe qui peut vérifier
     ou réfuter.
   - Évaluation par les pairs réelle : les revues de code, les issues et les PR sont un arbitrage
     plus exigeant que bien des comités de lecture.
   - Les données du monde réel arrivent à vous : cas adversariaux, bogues sur architectures
     exotiques — impossible à obtenir en vase clos.

3. Étude de cas concrète (3-4 min) — Une seule, racontée en profondeur : simdjson.
   Le cycle : code -> blogue / X / GitHub -> adoption -> article -> goulot suivant -> et ça
   recommence.
     -> analyse lente des nombres -> algorithme Eisel-Lemire -> adoption massive
     -> validation UTF-8 -> simdutf -> adoption massive

4. Tensions honnêtes (1-2 min) — maintenance ingrate, incitatifs académiques mal alignés (les
   comités comptent les articles, pas les PR).


Biographie :

Daniel Lemire est professeur d'informatique à l'Université du Québec (TELUQ). Ses travaux de
recherche et d'ingénierie portent sur le calcul haute performance, les structures de données
efficaces et l'optimisation de la performance logicielle. Il est l'auteur de bibliothèques libres
largement adoptées : on trouve ses algorithmes et son code dans plusieurs bibliothèques standards
et systèmes majeurs, dont .NET, Rust, Go, Node.js, Google Chrome et Safari. Il figure parmi les
2 % de scientifiques les plus cités au monde selon le classement Université Stanford / Elsevier.
Il est rédacteur de la revue Software: Practice and Experience (Wiley, fondée en 1971) et a reçu
le Prix d'excellence en recherche 2020 de l'Université du Québec pour ses travaux sur
l'accélération du traitement des documents JSON. Sur GitHub, il fait partie des 1000 développeurs
les plus suivis parmi plus de 100 millions. Il est @lemire sur X et tient un blogue hebdomadaire
à l'adresse https://lemire.me/.
